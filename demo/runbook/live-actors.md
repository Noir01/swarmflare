# Live actors (local and approved Cloudflare Workers)

Run from the repository root. The session worker owns the root and provisions `manifest.json` plus private role configs; do not hand-edit or copy credentials. Invoke:

  npx tsx demo/live/actor.ts ROOT ROLE COMMAND [JSON|@JSON_FILE]

Allowed roles are `api`, `ui`, `adversary`, and `reviewer`. The actor bridge reads only `ROOT/actors/<ROLE>.json` for the selected role. It refuses `human` and `runner`, malformed configs, human-only commands, and runner operations. By default `baseUrl` must be literal HTTP loopback; remote use requires both `baseUrl` and `approvedOrigin` set to the same exact HTTPS `*.workers.dev` origin (no port, path, userinfo, query, or fragment). Example shape: `{"baseUrl":"https://worker.account.workers.dev","approvedOrigin":"https://worker.account.workers.dev","projectId":"...","token":"...","actorId":"reviewer","repository":"..."}`. Use only the provisioned reviewer role config; do not hand-edit or copy credentials. It starts only the existing joined `apps/cli/index.ts` process with bounded time and a sanitized environment; it never starts a model or service. The role token is the identity presented to the server and the server remains the authorization authority.

Run `npx tsx demo/live/actor.ts ROOT ROLE --help` for a credential-free, role-scoped command list and executable payload shapes. Help does not read role config or contact a service. In `context`, inspect existing decisions; `decision {"requestId":"...","payload":{...}}` creates a decision and is not a read. Finding-repair uses `payload.revisions` with exact `{changeId,revisionId}` pairs; finding-resolve uses `payload.viewId` and `payload.note`; review anchors include `viewId`, `manifestDigest`, `composedCommitOid`, `treeOid`, `contractVersion`, and `policyVersion`. For large or less error-prone payloads, pass `@JSON_FILE`: the bridge reads a regular, non-symlink file of at most 64 KiB, parses it as inert JSON, and resolves relative paths from the caller's current directory. Never put credentials in an input file. Raw JSON arguments remain supported. Do not use generic `mutate` or human/runner commands. `resolve-decision` is human-only. Acknowledge only decisions actually reviewed. Do not fabricate conversation, evidence, checks, source receipts, or human approval.

Implement independently in the assigned source checkout, run the project checks, then publish real source with the existing Git workflow: create a change and publish a revision referencing the actual commit/tree OIDs (see `demo/runbook/runner.md` for runner-owned source-job workflows). The trusted runner composes explicit published revisions and records real checks. The reviewer reads the resulting View/evidence and submits a genuine review. Human confirmation/acceptance remains separate. Preserve each command's JSON response and report actual failures; never expose role config, token, or raw child output to a role that might contain secrets.
