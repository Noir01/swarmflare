# Bounded Cloudflare demo deployment runbook

This is the isolated `git-collaboration-demo-c29` deployment configuration, not the local `wrangler.jsonc`. The authorized account ID is `cb50a73b7487ae7039cbc8b613986b8b`. The namespace value in `wrangler.demo.jsonc` is intentionally the invalid-to-operate placeholder `REPLACE_WITH_CREATED_ARTIFACTS_NAMESPACE_ID`; never deploy until the coordinator replaces it with the provisioned namespace name/ID and checks the exact target. The `vars` map is empty; absent `DEMO_EXPIRES_AT` makes every request return 410. No credentials or secrets belong in this JSONC.

## Exact config contract (Wrangler 4.145.0 installed schema)

`artifacts` is an array; each object requires `binding` and `namespace`, optionally accepts boolean `remote`, and rejects additional keys. The configured entry is `{ "binding": "ARTIFACTS", "namespace": "<provisioned namespace>", "remote": false }`. `remote` only controls using the remote service in local dev. DO config uses `durable_objects.bindings` with `name: PROJECTS`, `class_name: Project`, and initial SQLite migration `new_sqlite_classes: ["Project"]`. `limits` accepts `cpu_ms` and `subrequests`; this config sets only `cpu_ms: 100`. It contains no cron triggers, routes, services, asset upload, or autoprovision directive. `workers_dev: true` is deliberately limited to the named demo Worker; `preview_urls: false`.

## Provision/deploy sequence (coordinator only)

No cloud calls were made in this implementation window. User authorization permits the tiny project demo, but the coordinator must provision and read back resources; this worker did not use any real credentials, perform auth or billing calls, or obtain human acceptance.

1. Use the coordinator's already-authorized Cloudflare profile, scoped to the literal account ID above. Do not print tokens or put them in command arguments, shell history, source, logs, or config. `cf auth whoami --profile <profile>` and `cf auth list` are local/auth-status checks; `cf` profile selection is `--profile`. The installed `cf` CLI offers no Worker upload command/schema (`cf workers scripts` only exposes `search`). Wrangler 4.145.0 is the supported Worker uploader and its deploy command accepts `--profile`; coordinator must confirm that its Wrangler profile resolves to the same authorized account before any write. Do not start an OAuth flow or create new auth in this runbook.
2. Create one isolated Artifacts namespace and one repository, then read both back. CLI syntax from installed help: `cf artifacts namespaces create --namespace git-collaboration-demo-c29 --jurisdiction us --profile <profile>`; `cf artifacts namespaces repos create git-collaboration-demo-c29 --name git-collaboration-demo-c29 --default-branch main --description "git-collaboration demo c29" --read-only false --profile <profile>`. Commands without `--dry-run` write; do not run until coordinator is ready. Capture the exact namespace name/ID and repo remote from readback. The API schemas confirm namespace POST body fields `namespace` (required), `jurisdiction` (optional); repo POST body `name` (required), `default-branch`, `description`, `read-only` (optional). `cf artifacts namespaces repos tokens` currently only lists; it exposes no token-create CLI command. Do not invent one or use the raw API here: use the installed Wrangler Artifacts binding/runtime or coordinator-approved supported token flow after verifying its schema.
3. Replace only the namespace placeholder in this config with the read-back binding target. Check account ID/name again. Supply `ARTIFACTS_SOURCE_CONFIG` securely as a Worker secret with projectId, repository, remote, and `allowWrites: true` (see `apps/worker/src/artifacts/source.ts`); put the repository token only into the approved secret mechanism, never the config. Provide `AUTH_CREDENTIALS` and `DASHBOARD_SESSION_KEY` using the secret store/secure input path approved by coordinator, not source/config/CLI literal arguments. Set `DEMO_EXPIRES_AT` as a finite future integer epoch-millisecond deadline in the deployment secret/config controls; absent, malformed, non-finite, or elapsed values fail closed (410). Keep demo credentials short-lived and project-scoped.
4. Run local checks first: `npx wrangler deploy --config wrangler.demo.jsonc --dry-run`. Actual upload, only after all placeholders, secret provisioning and target/account readbacks: `npx wrangler deploy --config wrangler.demo.jsonc --profile <wrangler-profile> --strict`. Do not use `cf deploy` (it is a distinct build-output workflow), do not pass `--secrets-file` with plaintext credentials, and do not use `--keep-vars` or configure any external routes/triggers.
5. Coordinator verifies the created namespace/repo, Worker name/account/bindings, exact deployment/version, secret bindings presence without reading secret values, and authenticated request/expiry behavior. Share URL only with demo participants. Record resource IDs, creation/deployment readbacks, expiry and cleanup owner; delete only these newly created resources after the demo. No billing API or spend guarantee is implied.

Cloudflare CLI facts were inspected offline via `cf --help`, `cf workers scripts --help`, `cf artifacts namespaces/repo help`, `cf schema artifacts namespaces create`, `cf schema artifacts namespaces repos create`, and Wrangler `deploy --help`. No network/cloud/auth endpoint was invoked. Wrangler local dry-run verified config parsing/bundling and listed `PROJECTS` and `ARTIFACTS` bindings while leaving the namespace placeholder visible.
