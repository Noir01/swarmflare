# Cloud demo review story and handoff

## What this demonstrates

The platform coordinates tasks, claims, decisions, revisions, combined Views, source receipts, checks, findings, reviews, readiness and any later human decision. `demo/seed/` is a separate sample project-list API/UI: cursor pagination, legacy responses and tenant isolation. Cloud hosting does not itself prove sample correctness.

The sample began as a prepared fixture, not fresh parallel API/UI contributor work. The platform story includes an actual independent finding, owner-authored repair, replacement composition, mandatory checks, focused runtime probe, independent review and readbacks. Do not recast that as a fresh contributor campaign.

## Human handoff and freshness

Use `cloud-human-review.md` for the human's optional review steps. An authorized operator must deliver current access details directly and securely to the human; never place credential contents, private credential paths, or endpoint secrets in this documentation, reports, prompts, screenshots or recordings. Actual human login/review is unverified. Endpoint and credentials are bounded/expiring; availability is not promised. If unavailable, ask the authorized operator for a bounded renewal on existing resources; do not infer liveness from receipts.

In `packages/local-runner/review-artifact.ts`, source receipts are read and compared before building the artifact and read again before recording it; candidate and baseline are checked again at build completion. The supported preview is assigned a 120-second expiry (`expiresAt = Date.now() + 120_000`). Run `checks` once for initial mandatory-suite execution. For each repeat human-review window, use `CLOUD_REPAIR_CONFIG_FILE=<owner-only-config-file> /home/noir/.local/state/nix/profile/bin/node --import tsx demo/cloud/repair.ts refresh`. Refresh creates a fresh source verification and exact-source review artifact, reads existing checks/policy/readiness, and does not execute or re-record mandatory checks. Returned check resources are labeled historically recorded and are applicable only when their complete candidate/source/policy tuple matches; missing or mismatched resources are not treated as passing. The result reports actual readiness and blockers, evidence prepared, and no acceptance. Baseline/source drift is refused. Do not use `checks` as a repeat refresh command or create an additional accounting approval gate.
