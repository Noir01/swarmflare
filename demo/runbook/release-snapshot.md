# Local source snapshot helper

This library creates a deterministic tar archive and SHA-256 manifest from an explicit source allowlist. It is a local packaging utility, not an execution guard, signer, cloud upload client, or release-readiness check. The manifest status is deliberately `supported-local-not-cloud-accepted`.

From the repository root, after the coordinator freezes the source tree, exercise the callable API with:

```sh
node --import tsx --input-type=module -e 'import { writeFileSync } from "node:fs"; import { join } from "node:path"; import { createReleaseSnapshot } from "./packages/release-snapshot/index.ts"; const result = createReleaseSnapshot(process.cwd()); const out = process.env.TMPDIR ?? "/home/noir/.hermes/cache/scratch"; writeFileSync(join(out, "release-snapshot.tar"), result.archive); writeFileSync(join(out, "release-snapshot.manifest.json"), JSON.stringify(result.manifest, null, 2) + "\n"); console.log(result.manifest.snapshotId, result.manifest.files.length);'
```

The previous continuous25 archive was deterministic and clean-extraction tested on this host, but predates continuous26 source changes. Do not treat an older archive as a snapshot of current source. Identify each new snapshot by its external manifest and verification receipt; this source document intentionally does not embed its own archive hash. Do not run this against the working repository until the coordinator freezes the source tree. Archive and manifest are outputs, not checked-in artifacts.

Included roots: `apps/`, `packages/`, `tests/`, and `demo/`, plus the package/lock/config files, README, reuse provenance, and existing MIT notices for the selectively reused Gittifacts packages. The root `wrangler.demo.jsonc` is an optional explicit allowlisted file: it is included when it exists as a regular file and omitted when absent, so older/local source trees without it retain their prior snapshot contents. A symlink or other non-file at that path is rejected. Credentials, `.local/` state, source reports under `reports/`, and Wrangler local state (including `.wrangler/`) are intentionally excluded; do not put secrets in the demo config. A cloud deployment still requires private deployment configuration/credentials outside this archive and must be performed through the separately authorized process. Packaging does not imply deployment, cloud acceptance, or human acceptance, and this archive is not for public publication. The upstream source pin is `5f06eb4a5e425fdc4796774e3bd4284a0056288b`. Upstream notices are preserved verbatim; local adaptations remain described in `GITTIFACTS-REUSE.md`.

Included files use a source/document extension allowlist (`.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.json`, `.md`, `.py`, `.html`, `.css`, `.txt`, `.yml`, `.yaml`, `.toml`, `.jsonc`) plus exact `LICENSE` and `PROVENANCE.md` names. Excluded before traversal: all hidden path segments and `.git`, `.local`, `.execution`, `node_modules`, `reports`, `coverage`, `dist`, `build`, `.wrangler`, `.worktrees`, `__pycache__`, and secret-named paths including `.env*` and `.dev.vars*`. Unexpected extensions (including binary files and `.pyc`) are omitted. Any non-hidden symlink encountered under included roots or at an explicit root file is rejected. This does not inspect file contents for secrets; filename/path and extension allowlists are the boundary. Review manifest paths and archive before sharing. GNU tar is required; no project dependency is added. Archive and manifest are written under `$TMPDIR` (falling back to Hermes' supported scratch path shown above).

After dependencies are already installed, focused verification is `node --import tsx ./node_modules/vitest/vitest.mjs run --config vitest.config.ts tests/release-snapshot/snapshot.test.ts`. Tests cover byte-identical archives, manifest identity/content changes, excluded state/secrets/cache/binary files, symlink refusal, edge-case filenames, byte-for-byte manifest-to-extraction verification, and execution of an extracted `.mjs` fixture. They do not establish a full product build, cloud acceptance, or release readiness. For dependency installation/cache behavior, see the root README.
