# Native candidate qualification

Operator-only fixed C29 synthetic fixture; not a public import executor or human acceptance script. Existing generated synthetic identity and exact README repository are validated before account operations. Secrets are read only in-program from owner-only local files; never print them or pass real human credentials.

Run from repository root with the supported Node/Chromium/bubblewrap environment:

    node --import tsx demo/cloud/candidate-smoke.ts prepare
    node --import tsx demo/cloud/candidate-smoke.ts revision
    node --import tsx demo/cloud/candidate-smoke.ts view
    node --import tsx demo/cloud/candidate-smoke.ts checks

Phases persist request IDs before resource writes. Source materialization uses actual Artifacts Git objects and an exactly scoped 60-second read token, revoked in cleanup. Immutable seed/View refs have one UUID; revision refs contain exact Change UUID and Revision UUID. Invalid ref identifiers are refused, not normalized. No credentials belong in repository URLs, Git source, reports or screenshots.

Contribution uses an expiring repository contributor grant; execution uses a separate operator-issued 120-second, operation-capped runner session. Approval, source publication/composition, mandatory checks, review and final acceptance are separate authorities. Passing suites do not imply task intent or readiness.

Actual independent Luna review of the published prepared first-party candidate found a late tenant-switch response race and missing Previous navigation despite passing suites. `candidate-feedback.ts` records the exact failed review and anchored findings with a separate repository reviewer grant. `candidate-repair.ts` publishes a complete baseline-parented UI replacement without modifying the original View or baseline. Independent actual re-review found unsigned cursor offset tampering; that failed evidence was preserved and its finding later resolved only against the checked and independently reviewed signed-cursor replacement.

`cursor-repair.ts` builds the next local repair using per-handler random HMAC-SHA256 keys, exact cursor payload/schema/signature verification and preserved UI bytes. Cursors intentionally cease to work after handler/process restart; this demo is not a durable multi-worker cursor service. Self-contained tests reproduce the old in-range tamper and verify rejection, valid complete pagination and restart refusal. They do not require private native caches.

The deployed owner-only renewal endpoint and `candidate-renew.ts` explicitly renew the existing synthetic contributor and reviewer grants for 900 seconds. It rotates tokens, retains actor/repository/role, reads back scope and old-token denial, verifies unchanged source and logs out. It does not revive revoked grants, create a human session or grant runner authority. No perpetual renewal process exists.

The cursor repair was published/composed, but old UI/preview harnesses recreated its signing-key handler for every request and rejected valid second-page cursors. The updated harnesses record actual bounded responses through one sandboxed handler, then replay exact recorded queries in isolated Chromium; no response or signing key is fabricated. Fixed tenant-a/b, limit=2, page bounds, network refusal, CSP and original UI oracle remain. This is bounded recorded-response UI evidence, not arbitrary hosting. Its changed trusted digest requires owner+CSRF policy configuration and a distinct View pinned to the new policy version. Never relabel existing failed checks or reuse their policy applicability.

`node --import tsx demo/cloud/candidate-cursor.ts` explicitly reuses the exact published cursor revision after matching current generated policy/task/baseline and actor ownership. It reads current finding repair links before writes, skips exact already-linked revisions, uses version-bound request IDs, composes a new-policy View, verifies source, runs actual mandatory suites and builds/read-backs the bounded preview. Existing failed checks stop rather than being overwritten. It never changes policy, creates self-review/resolves findings, or performs confirmation/acceptance. Grant/ingress renewal and owner policy configuration are separate bounded operator actions.

Short-lived runner sessions have distinct actor IDs. Refreshing an expired supported preview through another authorized repository runner appends a newly attributed artifact rather than overwriting the earlier producer's record. Exact current View/source/policy/baseline, size and expiry guards still apply; latest valid artifact readback is required. This is not authority to modify another producer's evidence or perform human actions.

`node --import tsx demo/cloud/candidate-review.ts` is an explicit reviewer-only qualification/resume helper. It reads an operator-supplied actual independent model verdict, verifies exact source, current generated task/policy/check applicability, independence and linked repairs, then records/read-backs the review and each resolution. Already matching evidence resumes without resource writes. The model verdict's provenance is operator-supplied, not server attestation. It never logs in as a human or confirms/accepts.

`node --import tsx demo/cloud/cursor-capture.ts` navigates actual public repository/candidate links and captures Conversation, Files changed, Checks and Preview. It attaches the sandboxed iframe's own browser target/session to exercise Next, Previous and tenant switching. It reads sanitized receipts only; no credentials or owner actions are used.

Native qualification now includes actual source/check/UI repair, independent Luna review recorded through a separate reviewer actor, three exact-evidence finding resolutions, readiness true, unchanged baseline/older candidates, and public preview navigation. A matching reviewer helper resume made no resource writes. No final human decision was performed. Prepared first-party source is not a fresh agent implementation campaign; no arbitrary imported code was executed. A missing or failed verdict must never be replaced with a scripted passing verdict.
